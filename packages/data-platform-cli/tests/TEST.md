# Data Platform CLI Test Plan and Acceptance Evidence

The current branch extends the original foundation suite with all packaged business modules and the dynamic `capability <capabilityId>` registry. The historical TAP transcript below is retained as evidence for earlier foundation tasks; the latest fresh run is summarized here.

## Suites

- auth-project.test.js: 18 tests for config/auth/project/platform/doctor binding, secure input, sessions, and runtime cleanup.
- core-runtime-binding.test.js: 6 tests for aggregate-only construction and secure authentication ports.
- coverage-metadata.test.js: 2 tests for real registry source keys and historical command-label drift.
- database-runtime.test.js: 2 tests for keychain-only database passwords and fail-closed setup.
- full-e2e.test.js: 2 end-to-end workflows covering five real tarballs, installed execution, direct injection, and no-HTTP/listener/repository-read audits.
- keychain.test.js: 7 tests for namespacing, set/get/delete, unavailable backend, and no plaintext fallback.
- package.test.js: 1 test for package metadata, bin, and Node engine.
- paths-profile.test.js: 9 tests for OS paths, validation, mode-0600 persistence, selection, and secret rejection.
- registry-output.test.js: 12 tests for metadata, aliases, redaction, envelopes, JSON stdout, and exit codes.

- business-command-registry.test.js: 4 tests proving aggregate capability registration, session revalidation, anonymous platform alias handling, JSON dispatch, and exact 596-key API coverage.
- ontology-acceptance.test.js: 4 tests for the Skill-facing ontology/acceptance facades, deterministic contract validation, fail-closed write ports, and local installed dispatch.

## Realistic foundation workflow

Install the packed CLI into a temporary prefix, create a profile with a fake keychain/runtime, login, resolve exactly one project, select it, query profile and platform diagnostics, enter and exit REPL, and assert no HTTP server is started or contacted.
